# 浮漂锁定跟踪

`TrackingBobberFinder` 是 GUI 使用的增强查找器，复用核心 `BobberFinder` trait；控制台仍使用普通 `SearchBobberFinder`。配置在 `core/src/tracking_finder.rs`，可通过 `with_config` 注入，GUI 当前不提供这些参数的编辑入口。

## 每帧处理

1. 获取共享分类器和区域快照，截屏并按颜色条件生成匹配掩码。
2. 构建积分图，根据邻域匹配数量过滤稀疏笔画。
3. 对过滤后的点计分，根据当前状态执行全局搜索、确认或局部跟踪。
4. 发送带过滤后掩码的 FrameEvent，并把位图坐标转换为屏幕坐标返回。

每次只处理当前搜索范围：全局搜索使用用户区域，确认和锁定使用与用户区域相交的局部窗口。密度计算额外读取半径 3 的边缘邻域，保证局部边界结果与完整图像一致。匹配点超过 1000 的保护仅统计当前候选范围，框外大色块不会清空框内候选；重复警告最多每 5 秒一条。

颜色掩码、积分图和候选点缓冲区按尺寸复用；没有预览需求时不创建整图输出掩码。失败后需要全局重搜时，使用同一截图重新计算全局候选，保留原状态机语义。

## 默认配置

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `density_radius` | 3 | 密度窗口边长 7 像素 |
| `density_min` | 30 | 窗口至少 30 个匹配点才保留中心匹配点 |
| `confirm_frames` | 2 | 候选连续出现两帧才锁定 |
| `confirm_tolerance` | 15 | 确认帧间 X/Y 各自允许偏移 |
| `track_radius` | 80 | 跟踪候选窗口半径 |
| `jump_tolerance` | 40 | X/Y 各自允许的最大跟踪位移 |
| `lost_tolerance` | 1 秒 | 短暂丢失时沿用上次位置的墙钟时长 |

参数按像素和时间解释，未进行分辨率归一化；不得将自定义负半径或极端配置视为已经验证的输入范围。

## 状态转换

- `Searching`：在搜索区域内（未设置则全图）挑选最高分候选；进入 `Confirming`。配置确认帧数不大于 1 时直接锁定。
- `Confirming`：在候选附近匹配并检查位移容差；累计达到确认帧数后进入 `Locked`。失败则重新全局搜索。
- `Locked`：在上次位置 ±80 窗口内寻找最高分候选，检查 ±40 位移限制；命中则更新位置和最后命中时间。
- 锁定后短暂丢失：容忍期内返回旧位置；到期后重新全局搜索。超限跳变同样按丢失处理。
- `reset()`：无条件恢复 Searching，清除最后命中时间。

区域约束全局和局部搜索；运行中修改区域或分类器参数后，下一帧解除原锁定并重新确认。主流程在预观察开始及等待咬钩开始时各重置一次查找器。

## 回归验证

合成图像测试覆盖密集色块确认、稀疏笔画、小幅移动、遮挡、超时重搜、跳变、区域内外候选、框外大色块、区域变更解锁、局部密度与全图对拍，以及缓冲区复用。

可重复运行分类和密度阶段测量（不包含截屏、计分、PNG 编码和 IPC）：

```powershell
cargo test -p fishing-core --release --locked benchmark_search_areas -- --ignored --nocapture
```

本机同一实现处理合成图像的 100 次平均耗时：

| 截图尺寸 | 全图处理 | 161×161 局部处理 |
| --- | --- | --- |
| 960×440 | 2260µs | 121µs |
| 1280×620 | 4058µs | 154µs |
| 1920×980 | 11853µs | 139µs |

这是局部处理范围的对比，不是整个程序的提速比例。真实水面识别率、截屏和编码开销仍需在实际游戏环境测量。
