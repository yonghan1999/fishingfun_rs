# 架构与数据流

本文描述当前实现。Workspace 使用 Rust 2021；平台及可执行程序当前以 Windows MSVC 为目标。

## 依赖方向

```text
gui ───────┬──> core
           └──> platform-windows ──> core
console ───┬──> core
           └──> platform-windows
input-source ──> windows
```

`core::traits` 定义 `ScreenCapture`、`BobberFinder`、`BiteWatcher`、`KeySender` 和 `MouseController`。核心流程只依赖这些能力，Windows 层实现截屏和键鼠操作，测试通过内存图像和记录器替换真实桌面能力。

`CapturedFrame` 同时携带 RGB 位图及其屏幕原点。查找器内部使用位图坐标，对外的 `find()` 返回屏幕坐标；GUI 框选区域、帧掩码和准星使用位图坐标。坐标转换在查找器出口完成。

## 钓鱼流程

`FishingBot` 注入浮漂查找器、咬钩观察者、键盘和鼠标实现。启动时执行十分钟宏键，然后循环：

1. 周期宏键到期则执行，发出 Cast 事件并发送抛竿键。
2. 重置查找器并观察约 2 秒，此阶段丢弃识别结果。
3. 再次重置，最多等待约 5 秒查找浮漂，用初始位置建立咬钩基线。
4. 持续查找浮漂并判断下沉；咬钩时右键初始浮漂位置，输入成功后发 Loot 事件，或在约 25 秒后结束等待并重新抛竿。输入失败取消会话并向 GUI 报告原因。

`PositionBiteWatcher` 对出现过的**不同 Y 值**排序，用索引 `floor((count+0.5)/2)` 取基线。`基线Y-当前Y <= -strike_value` 时触发咬钩。屏幕 Y 向下增长，因此上浮不触发。该算法保留了 C# 行为，不是对每帧样本求加权中位数。

`TimedAction` 可注入 `Clock`，默认用 `Instant`，测试使用 `ManualClock`。动作间隔使用严格大于判断，总时长使用严格小于判断。

## 查找与分类

`PixelClassifier` 提供红/蓝模式，按通道乘数和其余通道接近程度过滤像素。检测到 Classic 进程时，两个乘数设为 1；其他情况使用默认 0.5、2。

- 控制台使用 `SearchBobberFinder`：优先查找上次位置的 ±40 像素区域，未命中后恢复全图搜索。
- GUI 使用 `TrackingBobberFinder`：增加密度过滤、多帧确认、局部跟踪和丢失容忍，详见[跟踪说明](tracking.md)。

两者复用网格分桶计分：统计每个候选点满足 `abs(dx)<10 && abs(dy)<10` 的邻居数，同分保留扫描顺序的首个点。测试与朴素 O(n²) 参考实现对拍。单帧有效匹配点超过 1000 时按颜色配置异常处理。

## GUI 通信

Tauri 后端通过 `AppState` 共享分类器、搜索区域及机器人句柄。运行中的分类器和区域使用 `Arc<RwLock<_>>`，查找器每帧读取快照，避免逐像素加锁；抛竿键通过共享 Mutex 更新，停止标记使用 AtomicBool。

后台线程通过最新帧槽、标准库事件通道和有界日志通道，将以下数据桥接到 Tauri 事件：

| 事件 | 内容 | 前端用途 |
| --- | --- | --- |
| `frame` | PNG Base64、匹配高亮和准星、平均色、浮漂位图坐标 | 截图预览 |
| `session-event` | 短码 C、R、M、L（依次对应 Cast、Reset、BobberMove、Loot），含幅度 | 清图、曲线、拾取动画 |
| `log` | tracing 文本 | 日志列表 |
| `bot-stopped` | 机器人退出通知 | 恢复按钮状态 |
| `bot-status` | 状态变更通知，前端重新调用 `bot_status` | 当前状态和实际生效阈值 |
| `bot-error` | 会话启动、输入或清理错误 | 底部错误提示 |

查找器在生产端按 66ms 间隔生成预览掩码并投递到容量为一的最新帧槽，新帧覆盖未消费的旧帧；编码线程直接消费图像所有权，避免额外整图克隆。只有预览帧生成全尺寸掩码。日志队列容量为 512，满时丢弃日志，不阻塞识别；前端仅保留最近 500 条。普通钓鱼事件仍使用独立通道。识别循环之间保留可取消等待，关闭拟人化时 10ms，开启时 8..=25ms；预览频率不代表识别频率。

GUI 在创建线程前保留唯一会话，状态为 Starting/Running/Stopping；会话占位直到工作线程退出并清理后才解除。取消信号单向生效，启动不能清除停止请求；新一次开始创建全新会话。预观察、寻找浮漂、启动延迟和拾取等待均支持取消；系统截屏调用及已经按下后的配对释放仍需完成。

## Windows 层

截屏使用主屏桌面的 GDI `BitBlt` 和 `GetDIBits`，将 BGRA 转为 RGB。DC、位图和选择状态由作用域守卫管理，调用失败同样释放；读取位图前先解除选择，并检查完整扫描行数量。识别截屏失败时限频记录日志并返回 1×1 空帧；配置窗口直接调用 `try_capture`，失败返回可见错误。

键盘、光标移动和右键通过 `SendInput`。会话启动时绑定目标 PID/HWND，等待前台归属后发送启动空格；每次新输入前重新检查目标。鼠标移动或点击失败向上传递，不再继续后续点击；右键前检查光标位置未偏离目标、落点窗口属于目标进程。失焦时停止，不再向其他窗口发送恢复焦点的右键消息。已按下的键鼠用配对释放及作用域守卫清理。该检查与 SendInput 不具备原子性。

取消信号包含可选会话截止时刻，核心循环及平台等待共享同一截止时刻。GUI 关闭时先取消、等待会话和桥接线程清理，再退出；超时保留窗口。`input-source` 独立观察收到的输入来源，不参与机器人依赖链。
